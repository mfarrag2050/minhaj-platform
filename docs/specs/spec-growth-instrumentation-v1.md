## 0 · لماذا الآن، ولماذا لا يمكن تأجيلها

هذه المواصفة لا تبني أدوات تسويق. تبني **الالتقاط**: البيانات التي لو لم تُجمَع في لحظة حدوثها ضاعت إلى الأبد.

الفرق حاسم:
- **لوحة تحليلات** تُبنى في أي وقت فوق بيانات موجودة → **تُؤجَّل بلا خسارة**.
- **مصدر أوّل زائر** لا يُستدرَك بعد أن أغلق المتصفّح → **يُلتقط الآن أو لا يُلتقط أبداً**.
- **موافقة وليّ أمر** على استخدام مقطع ابنه في إعلان لا تُطلَب بأثر رجعيّ من 500 عائلة → **تُبنى في التسجيل**.
- **درجة قراءة الطالب قبل البرنامج** لا يمكن قياسها بعد أن تعلّم → **تُؤخذ في اليوم الأول أو يسقط الدليل**.

المنتج ينزل سوقاً أوروبيّة تسأل عن الدليل قبل السعر. هذه الطبقة هي التي تحوّل **الوعد** إلى **رقم موثَّق**.

## 1 · النطاق

**داخل النطاق:** إسناد المصدر · الموافقات المُجزَّأة بالغرض · أختام مراحل القمع · التقييم المهيكل (دخول/خروج/انتقال) · الإحالة · متطلّبات بنيويّة للغات والـSEO · قواعد خصوصيّة القياس.

**خارج النطاق (يُبنى فوقها لاحقاً):** لوحات التحليلات · أتمتة البريد والحملات · برنامج ولاء · تكامل إعلانات · تقارير BI.

## 2 · نموذج البيانات

### 2.1 `minhaj_attribution` — من أين جاء

صفّ واحد لكل **موضوع** (`subject`): زائر مجهول (بمعرّف كوكي) ثم يُدمج في المستخدم عند التسجيل، ثم يُنسخ لقطةً على الطلب عند الشراء.

| الحقل | ملاحظة |
|---|---|
| `id` | |
| `subject_type` / `subject_id` | `visitor` \| `user` \| `order` |
| `first_utm_source` / `_medium` / `_campaign` / `_content` / `_term` | **أوّل لمسة** — لا تُكتب فوقها أبداً |
| `first_referrer` / `first_landing_path` / `first_seen_at` | |
| `last_utm_*` / `last_referrer` / `last_landing_path` / `last_seen_at` | **آخر لمسة** — تُحدَّث كل زيارة |
| `referral_code` | إن دخل عبر إحالة — انظر §2.5 |
| `market` / `locale` | السوق المستهدف ولغة الواجهة عند أوّل لمسة |
| `raw_json` | ما لم يُنمذَج بعد — حتى لا نخسر ما لم نتوقّعه |

**قاعدة الدمج**: عند تسجيل زائر، ينتقل صفّه إلى `user` بأوّل لمسة **كما هي**. عند الشراء تُنسَخ لقطة إلى `order` — فتبقى صحيحة حتى لو تغيّر سلوك المستخدم بعدها.

**لا تُخزَّن IP كاملة.** تُجزَّأ أو تُقصّ (`/24`) — تكفي للسوق ولا تكفي للتعريف.

### 2.2 `minhaj_consents` — الموافقات مُجزَّأة بالغرض

**كل غرض موافقة مستقلّة.** خلطها في مربّع واحد يُبطلها قانوناً ويُفقدك استخدامها.

| الغرض (`purpose`) | ماذا يبيح |
|---|---|
| `service_terms` | استخدام المنصّة (أساس تعاقديّ لا موافقة) |
| `session_recording` | تسجيل الحصّة **للغرض التعليميّ والرقابيّ** فقط |
| `recording_marketing_use` | استخدام مقطع من الحصّة في مادّة ترويجيّة — **منفصل تماماً** |
| `testimonial_use` | نشر شهادة وليّ الأمر باسمه أو باسم مستعار |
| `marketing_email` | رسائل ترويجيّة بالبريد |
| `marketing_messaging` | واتساب/تليجرام ترويجيّ (غير التقارير التشغيليّة) |
| `child_photo_use` | صورة الطفل — **الافتراض: مرفوض، ولا يُطلب إلا لحاجة حقيقيّة** |

| الحقل | ملاحظة |
|---|---|
| `user_id` (وليّ الأمر) / `subject_student_id` (إن كان عن قاصر) | |
| `purpose` · `granted` (bool) | |
| `granted_at` / `withdrawn_at` | السحب حالة لا حذف |
| `policy_version` | نسخة النصّ الذي وافق عليه — بدونها الموافقة لا تُثبِت شيئاً |
| `locale` | اللغة التي عُرض بها النصّ |
| `method` | `signup_form` \| `admin_recorded` \| `email_link` |
| `evidence_hash` | بصمة (وقت + نسخة + معرّف جلسة مجزَّأ) |

**قاعدة صلبة:** لا يُستخدم أيّ محتوى تسويقيّاً ما لم يكن هناك صفّ `granted=1` غير مسحوب للغرض **نفسه**. الفحص في الكود لا في ذاكرة الموظّف.

### 2.3 `minhaj_funnel_events` — أختام المراحل

| المرحلة | متى تُختَم |
|---|---|
| `visited` | أوّل زيارة (بمعرّف زائر) |
| `lead_captured` | ترك بريداً أو هاتفاً |
| `trial_requested` / `trial_attended` | إن اعتُمدت الحصّة التجريبيّة (سؤال مفتوح §6) |
| `purchased` | اكتمال الدفع |
| `group_assigned` | أُسند إلى مجموعة |
| `started` | حضر أوّل حصّة فعليّاً |
| `midpoint` | أنجز 50% من الحصص |
| `completed` | أنهى البرنامج |
| `renewed` | اشترى مستوى تالياً |
| `churned` | انقطع بلا إكمال (بتعريف زمنيّ صريح) |

`id` · `subject_type`/`subject_id` · `stage` · `occurred_at` · `meta_json` · `attribution_id`.

**كل ختم مرّة واحدة** لكل موضوع (فهرس فريد على `subject + stage`) — نريد **متى وصل** لا كم مرّة مرّ.

هذه الأختام هي التي تُنتج لاحقاً: معدّل التحويل لكل قناة، زمن التحويل، **معدّل الإكمال لكل دفعة** — وهو أثمن رقم تملكه أمام مؤسسة أوروبيّة.

### 2.4 `minhaj_assessments` — آلة الإثبات

**هذه أهمّ طاولة في المواصفة كلّها.** بدونها يبقى «36 ساعة» ادّعاءً.

| الحقل | ملاحظة |
|---|---|
| `student_id` / `group_id` / `batch_id` | |
| `type` | `entry` \| `exit` \| `level_transition` |
| `assessed_at` / `assessor_id` | |
| `scores_json` | **درجات مهيكلة على معايير مسمّاة** — لا نصّ حرّ |
| `total_score` / `max_score` | للمقارنة والتجميع |
| `recording_ref` | مرجع الفيديو (قرار 4: انتقال المستوى باختبار + فيديو + تقييم مكتوب) |
| `notes` | نصّ المعلّم — للتشغيل لا للإحصاء |

**قيد:** لا تنتقل مجموعة إلى `active` وفيها طالب بلا تقييم `entry`. تقييم الدخول ليس إجراءً إدارياً بل **خطّ الأساس** الذي يُقاس عليه كل ادّعاء تسويقيّ لاحق. فوّته اليوم واخسر الدليل إلى الأبد.

**المعايير نفسها ليست قراري ولا قرار المبرمج** — يضعها فريق منهاج التربويّ. انظر §6.

### 2.5 `minhaj_referrals`

`code` (فريد) · `owner_user_id` · `active` · `uses_count` · `reward_type` (مؤجَّل) · `created_at`.
الرمز يُلتقط في رابط الهبوط ويُخزَّن في `attribution.referral_code`، ويُربط بالتحويل عند الشراء.

## 3 · قواعد ثابتة

- **G-1** أوّل لمسة لا تُكتب فوقها أبداً. آخر لمسة تُحدَّث دائماً.
- **G-2** لقطة الإسناد على الطلب تُجمَّد عند الشراء.
- **G-3** كل ختم مرحلة فريد لكل موضوع.
- **G-4** لا استخدام تسويقيّ لأيّ أصل بلا صفّ موافقة سارٍ للغرض نفسه. السحب فوريّ الأثر.
- **G-5** لا اسم طفل ولا معرّفه الحقيقيّ في أيّ حدث تحليلات خارجيّ ولا أيّ رسالة تسويقيّة. **معرّفات مجزَّأة فقط.**
- **G-6** لا مجموعة `active` بلا تقييم `entry` لكل عضو.
- **G-7** IP لا تُخزَّن كاملة.
- **G-8** لكل جدول هنا **مدّة احتفاظ معلنة** وحذف آليّ عند انتهائها.
- **G-9** الموافقة تُسجَّل مع **نسخة النصّ ولغته** — موافقة بلا نسخة لا تُثبِت شيئاً.

## 4 · التكامل

الوحدة **تستمع** ولا تُستدعى: `minhaj_group_activated` · `minhaj_group_member_added` · `minhaj_group_completed` · `woocommerce_order_status_completed` · `user_register`. كل مستمع يختم مرحلته.

نقطة التقاط الإسناد: سكربت خفيف يكتب معرّف زائر (كوكي أوّل طرف، بلا تتبّع عبر المواقع) ويرسل اللمسة إلى نقطة REST خاصّة بنا — **لا اعتماد على طرف ثالث في التقاط ما نملكه**.

## 5 · متطلّبات بنيويّة (تُقرَّر الآن، تُنفَّذ مع الموقع)

- رابط مستقلّ لكل لغة + `hreflang` صحيح متبادل + `x-default`. لا لغة داخل معامل استعلام.
- صفحة هبوط لكل **سوق × لغة**، وقابليّة إنشاء صفحات حملات بلا تدخّل مبرمج.
- بيانات مهيكلة `Course`/`Organization` بلا ادّعاء نتائج غير موثّقة.
- **صياغة الادّعاء**: «36 ساعة» تُعرض **نتيجةً نموذجيّة موثّقة** مع رقم الإكمال الفعليّ، لا ضماناً. هذه صياغة قانونيّة قبل أن تكون تسويقيّة.
- موافقة الكوكيز الأوروبيّة: لا سكربت تتبّع قبل الموافقة؛ التقاط الإسناد الأوّليّ يبقى في حدود ما يُباح بلا موافقة (كوكي أوّل طرف وظيفيّ) — يُراجَع قانونيّاً.

## 6 · معايير القبول

1. زيارة برابط `?utm_source=x&utm_campaign=y` ثم تسجيل ثم شراء ⇒ ثلاثة صفوف إسناد مترابطة، وأوّل لمسة سليمة في الثلاثة.
2. زيارة ثانية من قناة أخرى ⇒ آخر لمسة تتغيّر، أوّل لمسة لا تتغيّر.
3. سحب `marketing_email` ⇒ استدعاء «هل يجوز الإرسال؟» يعيد رفضاً فوراً.
4. محاولة استخدام تسجيل في مادّة ترويجيّة بلا `recording_marketing_use` ⇒ منع على مستوى الكود.
5. لا حدث تحليلات يحمل اسم طفل أو معرّفاً غير مجزَّأ (اختبار آليّ يفحص الحمولة).
6. تفعيل مجموعة وفيها عضو بلا تقييم `entry` ⇒ يُرفض.
7. تقرير دفعة يُخرج: عدد البادئين، المكملين، **معدّل الإكمال**، ومتوسّط الفارق بين تقييم الدخول والخروج.

## 7 · أسئلة مفتوحة تحجب التنفيذ

1. **معايير التقييم** — ما بنود تقييم الدخول والخروج ودرجاتها؟ **هذا سؤال لفريق منهاج التربويّ لا لنا**، وهو يحجب §2.4 وكل ادّعاء تسويقيّ لاحق.
2. **هل توجد حصّة تجريبيّة؟** يغيّر شكل القمع ومراحله.
3. **تعريف `churned`** — بعد كم أسبوع غياب؟
4. **حافز الإحالة** — خصم؟ حصّة مجانيّة؟ يحدّد `reward_type`.
5. **مدد الاحتفاظ** لكل جدول — تحتاج مراجعة قانونيّة قبل التثبيت.
6. **الأسواق الأولى** — تحجب صفحات الهبوط، ومشتقّة من **جرد لغات المعلّمين الستّين** الذي لم يُنجز بعد.
