# ملحق `spec-organizations-v1` — نموذج التعويض القابل للضبط

**الحالة:** مسوّدة للدمج · **التاريخ:** 28 أغسطس 2026 · **المصدر:** قرار 16 (موقف المرحلة) + قرار 13 (تعدّد الجهات)

> ⚠️ **مكتوب من خارج المستودع.** أسماء الجداول والحقول القائمة مذكورة كما وردت في الـskill؛ **تحقّق منها في الشيفرة قبل التنفيذ** ولا تفترض تطابقاً.

---

## 1. لماذا هذا الملحق

قرار 16 يقول: **أجر المعلّمين يُضبط بالكامل وفق العقد، ولكل فريق نُدخله يُتَّفق مع المؤسسة على شكل التعاون مع المعلّم على حدة.**

هذا **ليس تفصيلاً مؤجَّلاً بل مواصفة**: النظام يجب ألّا يعرف نموذج أجر واحداً. لو بُني بافتراض «بالساعة» لانكسر عند أوّل جهة تعمل بالحصّة أو بالطالب أو براتب شهريّ — والانكسار سيكون على **بيانات إنتاج فيها مال مستحقّ**، وهو أسوأ وقت للترحيل.

**المبدأ الحاكم:** النظام يسجّل **وقائع**، والسياسة تترجمها إلى **استحقاقات**، والإنسان يعتمد **التسوية**.

```
واقعة (جلسة انعقدت) → سياسة الجهة → استحقاق (سطر مجمَّد السعر) → تسوية (فعل بشريّ)
```

## 2. ما يُضاف إلى `organizations`

| الحقل | النوع | الغرض |
|---|---|---|
| `supplies_teachers` | bool | الجهة تورّد معلّمين |
| `refers_students` | bool | الجهة تجلب طلاباً |
| `default_currency` | char(3) | عملة التسوية معها |
| `settlement_period` | enum(`monthly`,`per_cohort`) | دورة التسوية |

جهة واحدة قد تكون الاثنين (قطر اليوم). **الإسناد ليس ملكيّة (قرار 13)**: الطالب لنا، والجهة تُحاسَب لا تملك.

## 3. الجداول الثلاثة الجديدة

### 3.1 `minhaj_org_comp_policies` — السياسة

سياسة واحدة نافذة لكل (جهة، نطاق) في أيّ لحظة.

| الحقل | ملاحظات |
|---|---|
| `policy_id` | PK |
| `organization_id` | الجهة **الموردة للمعلّم** |
| `scope` | `organization` \| `teacher` \| `group` — الأضيق يغلب |
| `teacher_id` / `group_id` | حسب النطاق، وإلا NULL |
| `basis` | `per_session` · `per_student_session` · `per_hour` · `per_month` · `per_enrollment` |
| `unit_rate` | DECIMAL(12,4) |
| `currency` | char(3) |
| `counts_no_show` | هل تُستحقّ حصّة انعقدت بحضور صفر؟ **قرار تعاقديّ لا هندسيّ** |
| `counts_admin_cancelled` | هل يُدفع عن إلغاء إداريّ متأخّر؟ |
| `max_billable_students` | سقف لـ`per_student_session` (مثلاً 5) |
| `min_billable_minutes` | لحماية `per_hour` من جلسة انقطعت |
| `rounding` | `none` \| `up_15m` \| `up_30m` |
| `effective_from` / `effective_to` | **السياسة مؤرَّخة، لا تُعدَّل بأثر رجعيّ** |
| `notes` | نصّ بند العقد المقابل |

**قيد في القاعدة:** فهرس فريد جزئيّ يمنع تداخل فترتين نافذتين لنفس (organization_id, scope, teacher_id, group_id).

### 3.2 `minhaj_teacher_accruals` — الاستحقاق

صفّ لكل واقعة استحقاق، **بسعر مجمَّد لحظة الإنشاء**.

| الحقل | ملاحظات |
|---|---|
| `accrual_id` | PK |
| `session_id` | NULL للأسس غير المرتبطة بجلسة (`per_month`) |
| `teacher_id` · `supplier_org_id` | من يُدفع له، وعبر أيّ جهة |
| `student_org_id` | الجهة التي جلبت الطالب — للمحاسبة العكسيّة |
| `policy_id` · `basis` | لقطة عن السياسة وقت الاستحقاق |
| `quantity` · `unit_rate` · `currency` | **مجمَّدة** — تغيير السياسة لاحقاً لا يمسّها |
| `amount` | **عمود مولَّد مخزَّن** = quantity × unit_rate |
| `status` | `blocked` \| `pending` \| `approved` \| `settled` \| `void` |
| `period` | `YYYY-MM` |
| `settlement_id` | NULL حتى التسوية |
| `actor_user_id` | صريح دائماً — لا `get_current_user_id()` (ينكسر في cron والـwebhooks) |

**قيد ازدواج في القاعدة:** فريد على `(session_id, teacher_id, basis)` حيث `status <> 'void'`. الـwebhook قد يصل مرّتين — القاعدة تمنع لا PHP.

### 3.3 `minhaj_settlements` — التسوية

`settlement_id` · `organization_id` · `period` · `currency` · `total_amount` (rollup) · `status` (`draft`/`approved`/`paid`) · `approved_by` · `approved_at` · `reference` · `note`.

**لا شيء يُدفع تلقائياً.** التسوية فعل بشريّ موثّق، والاستحقاقات تنتقل إليها بالاعتماد لا بالإنشاء.

## 4. القواعد السلوكيّة

1. **الإطلاق بعد COMMIT** — الاستحقاق يُنشأ من `Events::SESSION_COMPLETED` بعد إغلاق المعاملة، لا داخلها.
2. **جلسة بلا سياسة نافذة ⇒ `status = blocked` + تنبيه.** لا يُنشأ استحقاق بصفر ولا يُتخطّى بصمت. *(درس `aqop-portal`: n8n كان يبلّغ النجاح وهو متوقّف منتصف المسار.)*
3. **قرار 14 (نافذة التسامح)**: انقطاع المعلّم وعودته داخل النافذة = **جلسة واحدة ⇒ استحقاق واحد**. الانعقادان لا يولّدان صفّين.
4. **قرار 9**: الحصّة تُحتسب بانعقادها في **رصيد الطالب**. أمّا الأجر فيحكمه `counts_no_show` — **الفصل مقصود**، فما يستهلكه الطالب ليس بالضرورة ما يستحقّه المعلّم.
5. **العملة تُجمَّد** مع السعر. لا حساب معادل بسعر صرف اليوم عند العرض — إن لزم التحويل فبسعر مخزَّن لحظة الاستحقاق.
6. **تعديل السياسة يفتح فترة جديدة** ولا يعدّل القائمة. سجلّ التعديلات في `audit_log`.
7. **الأدوار**: `minhaj_view_accruals` (الجهة ترى استحقاقاتها فقط) · `minhaj_approve_settlement` (الإدارة العليا وحدها). النطاق يمرّ عبر بُعد الجهة في `spec-access-v1`.

## 5. ما لا يُبنى الآن

بوّابة دفع للمعلّمين · فوترة تلقائيّة · احتساب ضرائب أو اقتطاعات · تحويلات. النظام **يحسب ويعرض ويصدّر**، والدفع خارجه حتى يُوقَّع العقد ويُعرف اتّجاه المال.

## 6. اختبار القبول

- جهة `per_session` وأخرى `per_student_session` وثالثة `per_month` في القاعدة نفسها، وكلٌّ تُنتج الاستحقاق الصحيح من الجلسة نفسها.
- جلسة بحضور صفر: تُستهلك من رصيد الطالب، وتُستحقّ أو لا حسب `counts_no_show`.
- `webhook` مكرَّر لا يولّد استحقاقين (القيد يرفض).
- تغيير السعر اليوم لا يغيّر مبلغ استحقاق أمس.
- جلسة بلا سياسة ⇒ `blocked` + تنبيه، لا صفر صامت.
