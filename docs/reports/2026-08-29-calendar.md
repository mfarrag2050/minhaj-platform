## 1 · ما نُفِّذ

### وحدة `Minhaj\Modules\Calendar\`

- **الجداول الثلاثة** (spec §2): `minhaj_calendars`، `minhaj_calendar_days` (فريد على `calendar_id + day_date`)، `minhaj_group_calendars` (فريد على `group_id + calendar_id`). أربعة أعمدة أُلحقت بـ`minhaj_groups`: `holiday_behavior`، `no_calendar_ack_by/_reason/_at`.
- **الأصناف المجاليّة**: `CalendarStatus`، `CalendarDayKind`، `HolidayBehavior`.
- **`CalendarRepository`** كطبقة قراءة/كتابة وحيدة تخاطب `$wpdb`؛ `PersistenceException` بأنواع صريحة لكل قيد فريد.
- **`CalendarService`** يطبّق §1..§3 + §5 + تصحيحات المراجعة الست:
  - **C-1** ✅ اسم العمود `org_id` (لا `organization_id`).
  - **C-2** ✅ `acknowledge_no_calendar()` يشترط سبباً مكتوباً؛ الفلتر `minhaj_timetable_pre_generate_gate` يرفض التوليد حين لا تقويم ولا إقرار. `suggest_default_calendar_for_country()` يُتيح اقتراح تقويم افتراضيّ من `org.country`.
  - **C-3** ✅ `list_stale_calendars()` + `is_group_calendar_stale()` + الحدث `minhaj_calendar_stale_warning` يُطلَق أثناء التوليد.
  - **C-4** ✅ `set_holiday_behavior('skip_and_compress', …)` يشترط `MANAGE_GROUPS` + سبباً + غياب تسجيلات مدفوعة أو تجاوزاً صريحاً بسببه. الافتراض `skip_and_extend` لا يُقلَب بإعداد عامّ — لا فلتر، لا خيار، فقط استدعاء مؤتمَن.
  - **C-5** ✅ `delete_day()` داخل معاملة مع `count_held_sessions_on_calendar_date_for_update()` — لقطة قفل `FOR UPDATE` قبل الحذف.
  - **C-6** ✅ `create_calendar/add_day/delete_day` على تقويم `org_id IS NULL` تشترط `MANAGE_GROUPS`.
- **`GenerationHooks`** — الجسر بين Timetable وCalendar. يشترك في فلترَيْن (`pre_generate_gate` و`skip_dates_for_group`) وحدث staleness. Timetable لا يستورد Calendar مباشرة — فتظلّ حزمة الاختبارات الأدنى قابلة للتشغيل بلا هجرة التقويم.

### تعديلات على وحدات قائمة

- **`SessionTimeCalculator::generate`** يقبل الآن `skip_dates` اختيارياً. الشرط الحاسم: **المطابقة على `local->format('Y-m-d')` بعد الإسناد إلى `anchor_timezone`**، لا على UTC. المرشّح المرفوض لا يستهلك رقم تسلسل، فيبقى `sequence_no` بلا فجوات (§3.3).
- **`TimetableService::generate_for_group`** يستدعي:
  1. الفلتر `minhaj_timetable_pre_generate_gate` — بوّابة C-2. رفضٌ من الفلتر يعيد `WP_Error` مباشرةً.
  2. الفلتر `minhaj_timetable_skip_dates_for_group` — يقرأ التقاويم المرتبطة عبر Calendar module.
  3. الحدث `minhaj_timetable_check_calendar_staleness` — يوقظ حارس C-3.
  4. توسيع نافذة `weeks_count` إذا كانت `skip_dates` غير فارغة والسلوك `skip_and_extend` — يتمّ الوصول إلى `total_sessions` المتعاقَد عليها. إذا لا `skip_dates`، تحافظ الشيفرة على R-1 الأصليّ بلا تخفيف.
  5. للسلوك `skip_and_compress`: يقصّ إلى `total_sessions`، ويكتب العدد الفعليّ في عمود `minhaj_groups.total_sessions` (C-4).

### لم يُنفَّذ ولماذا

- **§4 `recalculate_from`** — مُقفَل بموسم Zoom. يستدعي إلغاء اجتماع وإنشاء آخر (spec-zoom-sessions-v1 §5 M-2). كتابته اليوم يعني كتابته مرّتين. **موسوم في المواصفة «بعد Zoom».**
- **لوحة الإدارة وأمر WP-CLI** — خارج نطاق هذه المرحلة كما فعلنا مع Orgs. الخدمة تعرض `list_stale_calendars()` وقفل الحذف — الأدوات مجرّد وصلات.
- **قسم §5 «طرح أيام التقويم من توفّر المعلّم»** — مضمَّن ضمنيّاً: أيام التقاويم لا تُولَّد، فالتوفّر عليها لا يُقاس أصلاً. لا يوجد اليوم استعلام مستقلّ يطرح أيام التقويم من `teacher_load`؛ يُترك للتقارير القادمة إن احتجناه.

### 3.2 §7 · اختبار تكامل حيّ لمنطقة زمنيّة بعيدة عن UTC + جلسة قرب منتصف الليل المحلّيّ

الأمر:
```
bash tests/Integration/calendar-anchor-timezone.sh
```

مجموعة أُنشئت في `Pacific/Kiritimati` (UTC+14 دون تحوّل صيفيّ) بجلسة تبدأ **00:30 محلّياً يوم الثلاثاء**. اليوم المحلّيّ الثلاثاء = يوم UTC الاثنين. تقويم يعطّل `2027-01-05` (الثلاثاء المحلّيّ). الناتج الحرفيّ:

```
== Reset relevant tables ==
== Seed: one supplier org + one group in Pacific/Kiritimati + a calendar with 2027-01-05 disabled ==
  ORG=39 GROUP=45 TEACHER=352 CALENDAR=5 DAY=5

== C-2 · generation refuses when no calendar attached and no ack on file ==
  GATE_RESULT=err:no_calendar
  ✓ C-2 gate rejects with err:no_calendar

== Attach the calendar + seed teacher availability at 00:00–02:00 Tuesday local ==
  wired

== Generate 3 sessions · anchor Pacific/Kiritimati · start 00:30 local Tuesday · disable 2027-01-05 ==
  ---
  GEN=ok count=3
  SESSION seq=1 local=2027-01-12 00:30:00 utc=2027-01-11 10:30:00
  SESSION seq=2 local=2027-01-19 00:30:00 utc=2027-01-18 10:30:00
  SESSION seq=3 local=2027-01-26 00:30:00 utc=2027-01-25 10:30:00
  ---
  ✓ generation succeeded with exactly 3 sessions
  ✓ no session on 2027-01-05 local — the disabled anchor day was skipped
  ✓ UTC dates differ from local dates — the boundary the anchor-tz rule guards is live
  ✓ session on 2027-01-12 local present
  ✓ session on 2027-01-19 local present
  ✓ session on 2027-01-26 local present

CALENDAR ANCHOR-TZ PROOF PASSED
```

قراءة السطر الحاسم: **`local=2027-01-12 00:30:00 utc=2027-01-11 10:30:00`** — التاريخ المحلّيّ 12، وتاريخ UTC 11. الفرق أربعة عشر ساعةً يُقصي يوماً كاملاً. لو استعملنا يوم UTC للمطابقة، ما اجتاز الاختبار — وهذا بالضبط ما يثبته اختبار الكسر التالي.

## 4 · الأسئلة المفتوحة

1. **`recalculate_from`** يستحق مواصفة توضيحيّة قبل تنفيذه: هل يعيد كتابة جلسات مستقبليّة أم يُلغيها ويستدعي التوليد التالي؟ الفارق ماليّ (استحقاقات نُشِرَت لطاقم مدفوع مسبقاً على جلسات مُلغاة). يُحسم مع spec-zoom-sessions-v1.
2. **تكرار الأعياد الإسلاميّة سنوياً** (C-3 يعالج الأثر لا السبب). هل نبني مستورداً؟ من أين نأخذ التواريخ الشرعيّة؟ أُجَّل إلى مرحلة أدوات الإدارة.
3. **دقّة `count_held_sessions_on_calendar_date_for_update`**: تعتمد على `CONVERT_TZ` في MariaDB الذي يتطلّب جدول `mysql.time_zone_name` مبذوراً. مبذور في بيئة `wp-env`؛ سنتحقّق منه في CI الإنتاج قبل إطلاق تفاعل C-5 بحساسيّة.
4. **سلوك «الطرح من التوفّر»** حين نبني تقارير أحمال المعلّم مستقبلاً: هل نتقاطع مع `list_disabled_dates_for_group` لكل المجموعات المتعاقَد عليها المعلّم؟ يُترك حتى تُطلَب تلك التقارير.
5. **الحالة الحدّيّة**: مجموعة `skip_and_compress` لها تسجيلات مدفوعة، ثم تغيّرت لاحقاً إلى `skip_and_extend` — هل `total_sessions` الذي صار مضغوطاً يعود؟ اليوم لا يعود تلقائياً. القرار: التغيير للخلف عمليّة إداريّة صريحة، تُوثَّق حين نبني الشاشة.
6. **رابط دور `minhaj_org_admin` بالتقاويم**: لا يستطيع مسؤول الجهة اليوم إنشاء أو تعديل تقاويم لجهته (لا يملك `MANAGE_GROUPS`، ولا نمنحه `MANAGE_ORG_CALENDAR`). سيُبَتُّ عند بناء شاشة التقاويم — إن قرّرنا أنّ الجهة تدير تقاويمها الخاصّة، نضيف قدرة جديدة.
